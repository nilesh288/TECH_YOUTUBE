1. ChatGPT never plans a full sentence, paragraph, or answer in advance.
2. Every response you see is generated by repeating a single mechanical task.
3. It calculates the probability of what token comes next.
4. In this video, we will walk through the exact pipeline ChatGPT uses to predict text, one token at a time.
5. ChatGPT is an auto-regressive language model.
6. This means it predicts the next piece of text based on all previous pieces.
7. The model calculates the probability of token T given tokens 1 through T - 1.
8. It does not understand ideas holistically.
9. Instead, it treats every prompt completion as an iterative statistical sequence problem.
10. The model does not read whole words.
11. It processes text as tokens.
12. A token is a fundamental unit of text; it can be a whole word, a syllable, or a single letter.
13. Neural networks cannot process raw text strings; they only understand numbers.
14. To fix this, the input text goes through a process called Byte Pair Encoding.
15. This process breaks text into discrete tokens.
16. Common words become single tokens; rare words, code, or complex word structures get broken into smaller multi-token fragments.
17. Each token is then mapped to a unique integer.
18. This happens using a vocabulary lookup table.
19. This table acts as a fixed dictionary containing roughly 100,000 tokens.
20. Every text fragment is swapped for its matching integer ID.
21. Those integer IDs are useless for math on their own.
22. The model uses an embedding lookup to translate each integer into a dense vector.
23. A vector is a list of thousands of floating-point numbers.
24. Imagine a high-dimensional coordinate map.
25. Tokens with similar meanings sit closer together on this map.
26. But Transformers process all input tokens at the same time; they do not read sequentially.
27. This creates an order problem.
28. To fix this, the model adds positional encodings to the vectors.
29. You can think of these as time-stamp tags.
30. They mark the sequential order of the tokens.
31. This ensures the model knows which word came first.
32. The vectors enter a stack of Transformer decoder layers.
33. These layers update the token representations step by step.
34. This happens through scaled dot-product attention.
35. The model creates three new vectors for each token; these are called the query, the key, and the value.
36. The query asks what context the token needs.
37. The key holds the information the token contains.
38. The model calculates attention weights by multiplying the query of the current token against the keys of all previous tokens.
39. This creates a relevance score.
40. But the model applies causal masking.
41. This strictly prevents the current token from looking ahead to future tokens.
42. Think of attention as a dynamic spotlight: each token highlights relevant prior tokens to resolve ambiguity.
43. It links a pronoun like "it" to a previous noun like "the database".
44. Finally, the model uses the value vectors of the highlighted tokens to update the current token.
45. Earlier context modifies the active position.
46. After passing through all layers, the vector hits a final linear projection layer.
47. This outputs an unnormalized score vector called logits.
48. There is one logit value for every single token in the 100,000-token vocabulary.
49. Next, a softmax function transforms these raw logits.
50. It converts them into a normalized probability distribution.
51. All the probabilities now sum to exactly 100%.
52. The model does not always pick the highest-scoring token.
53. A greedy search always picks the top token, but this can make text repetitive.
54. Instead, the model uses stochastic sampling to introduce randomness.
55. Settings like temperature and Top-P control this choice.
56. They balance creative randomness against strict determinism.
57. The model selects an output token.
58. That single token is then appended to the original prompt sequence.
59. This creates an enlarged sequence.
60. This new sequence is fed back into the Transformer network.
61. The entire process repeats to predict the next token.
62. Think of this like laying down train tracks one tie at a time immediately ahead of a moving train.
63. The model caches the past key and value vectors.
64. This is called KV caching.
65. It ensures the model does not recompute the entire history on every single iteration.
66. This recursive pass continues until a specific condition is met.
67. The loop stops when it predicts a designated end-of-sequence token.
68. It also stops if it hits a hard token limit.
69. Let us look at a concrete example.
70. Imagine the prompt is the phrase: "The software engineer fixed the".
71. First, the model tokenizes these words into integers.
72. Inside the Transformer, self-attention highlights the tokens for "software engineer" and "fixed" over generic filler words.
73. The network processes this context.
74. It outputs a probability distribution for the next token.
75. The token for "bug" gets 64%.
76. The token for "error" gets 22%.
77. The token for "issue" gets 10%.
78. The token for "sync" gets 0.0001%.
79. The sampling mechanism selects the token for "bug".
80. The word "bug" is concatenated onto the sequence.
81. The new input becomes: "The software engineer fixed the bug".
82. The model initiates the next inference pass using this updated text.
83. Full text generation is not holistic thought.
84. It is an iterative loop.
85. It vectorizes input, computes contextual attention weights, and samples from a vocabulary-wide probability distribution.
86. It builds the answer exactly one token at a time.
